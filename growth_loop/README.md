# Pantry Growth Loop

这个目录用来把“市场调研 -> 产品判断 -> 开发 -> 测试 -> 触达 -> 数据复盘”变成可重复执行的半自动流程。

## 目录约定

- `signals/`：当天收集到的信号，包括后台行为、识别样本、外部用户原声、竞品变化。
- `insights/`：从信号里提炼出的判断，包含目标用户、痛点、阻力、机会。
- `experiments/`：可执行的产品/增长实验，每个实验必须有假设、成功指标、停止条件。
- `prd/`：当前准备开发的需求说明。
- `qa/`：发布前检查清单和回归测试标准。
- `outreach/`：触达渠道、文案、带渠道参数的链接。
- `results/`：实验上线后的复盘。
- `scripts/`：可重复运行的数据整理脚本。
- `templates/`：新一天或新实验的模板。

## 每轮循环

1. 收集信号：运行后台复盘脚本，补充外部原声。
2. 生成洞察：判断本周最值得验证的人群和痛点。
3. 选实验：一次只做一个最小实验。
4. 开发测试：Codex 实现，跑 QA 清单。
5. 人类验收：体验、隐私、发布判断必须人工确认。
6. 触达用户：AI 生成文案和链接，人类手动发出。
7. 复盘结果：第二天和第七天看打开、录入、回访。

## 人类必须介入

- 选择目标用户和实验方向。
- 审核触达文案，手动发评论/私信/朋友圈。
- 体验验收和生产发布批准。
- 判断用户照片、识别样本、隐私授权是否可接受。

## 可自动化

- 后台行为复盘。
- 识别样本汇总。
- 外部原声整理。
- 候选实验生成。
- PRD/QA/触达文案草稿。
- 小范围代码改动、测试、部署检查。

## 常用命令

生成后台行为日报：

```bash
PANTRY_ADMIN_TOKEN=... node growth_loop/scripts/daily-report.mjs
```

生成渠道链接：

```bash
node growth_loop/scripts/make-campaign-links.mjs expiry_beta_20260508 xhs_comment friend_a friend_b friend_c friend_d
```
