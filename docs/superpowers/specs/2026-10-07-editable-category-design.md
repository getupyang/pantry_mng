# 添加页分类可编辑设计

记录时间：2026-10-07

## 目标

保留按品名关键词自动判断分类的行为，把护肤、护发等宽泛结果细化为用户盘点时实际使用的扁平分类，并让用户在添加物品页确认录入前修改自动分类结果。用户最终选择的分类写入现有 `cat` 字段，物品库继续按该字段分组展示。

## 范围

- 照片识别结果表单增加“分类”选择框。
- 手动录入表单增加同样的“分类”选择框。
- 输入或识别品名后，现有 `detectItem()` 结果自动预选对应分类。
- 用户可以覆盖预选值；确认录入时以选择框当前值为准。
- 分类选择框使用一份明确的扁平清单：面膜、面霜、眼霜、水、乳液、精华、洁面、护手霜、身体乳、防晒、香水、洗发水、护发精油、护发素、底妆、修容、口红、眼线笔、腮红、高光、假睫毛、散粉、定妆喷雾、口腔、清洁、纸品、其他。
- 常见品名关键词直接建议上述细分类，例如“补水面膜”建议“面膜”，“夜间保湿面霜”建议“面霜”，“安热沙防晒乳”建议“防晒”。
- 订单截图逐件确认时，每一件重新根据其品名预选分类，不继承上一件的人工选择。

## 不在本次范围

- 不新增分类 ID、父子分类或数据库字段。
- 不修改物品详情页。
- 不新增分类筛选器。
- 不迁移或批量改写已有物品。
- 不改变包装类型的选择与筛选逻辑。
- 不让视觉模型直接返回分类；仍使用当前的品名关键词规则。

## 交互行为

1. 用户手动输入品名，匹配到关键词后，分类选择框自动切换到推荐分类。
2. 用户可以在确认录入前改选任意分类。
3. 用户在分类自动预选后主动改选时，只要品名没有再次发生变化，系统不覆盖人工选择。
4. 用户再次修改品名时，系统重新运行现有自动分类：匹配成功则更新推荐，未匹配则选择“其他”；用户仍可再次修改。
5. 未匹配到分类时预选“其他”，不阻止录入。
6. 照片或订单识别填充品名后，同样触发分类预选。
7. 保存后的 `cat` 直接用于现有物品库分类标题，因此无需改造陈列结构。

## 实现边界

- `ITEM_CATEGORIES` 是两个选择框共享的明确选项来源；`DETECT_MAP` 只负责从品名产生自动建议，并补充与扁平分类对应的常见关键词规则。
- 两个添加表单共享同一份分类选项和设置逻辑，避免照片录入与手动录入行为分叉。
- `confirmAdd()` 不再直接采用临时检测结果中的 `d.cat`，而是读取当前可见表单的分类选择值。
- `shape`、`unit`、`dailyUse` 和配色仍来自现有检测规则；人工修改分类只修改 `cat`，不隐式改变这些库存计算参数。
- 埋点和识别反馈中的 `cat` 使用最终保存的用户选择。

## 兼容性

物品仍保存为原有 JSON 结构，只改变 `cat` 的可选值范围。Supabase 同步保存整份 `items` JSON，因此不需要数据库迁移。旧物品保持原值并继续正常显示。

## 验收标准

- 两个选择框都按既定顺序展示完整扁平清单，开头可直接看到“面膜、面霜、眼霜、水、乳液、精华、洁面”。
- 手动输入“补水面膜”“夜间保湿面霜”“紧致眼霜”“安热沙防晒乳”“丝绒口红”或“旅行洗发水”时，分别自动建议面膜、面霜、眼霜、防晒、口红和洗发水；改成“其他”后保存的 `cat` 为“其他”。
- 手动输入另一个能被现有规则识别的品名时，未修改分类则保存现有自动分类结果。
- 照片识别返回可匹配品名后，分类已预选且可以修改。
- 订单批量录入的下一件商品不会沿用上一件人工选择。
- 无法识别的品名默认保存为“其他”。
- 新物品在物品库中出现在最终选择的分类标题下。
- 包装类型必选、保存、筛选和刷新保留行为不受影响。
- 旧物品、JSON 导入导出和家庭云同步不需要迁移即可工作。
- 320、390 和 1280 像素宽度下，添加表单的分类选择框不溢出或遮挡。

## 验证层级

- Smoke：JavaScript 语法检查与页面加载。
- Touched suite：手动录入、照片结果填充、订单逐件重置、人工覆盖、保存值、物品库分组、包装类型回归和多宽度布局。
- 不运行全量回归；本次不修改库存计算、数据库结构或后端 API。

## 适用范围与过时风险

本设计适用于当前单 HTML 应用 `pantry.html`、明确维护的 `ITEM_CATEGORIES` 扁平清单及其基于 `items` JSON 的同步方式。如果未来分类改为服务端字典、稳定 ID 或多级分类，本设计中的字符串选项和兼容判断需要重新评估。
